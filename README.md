# ClaimCheck: health-plan benefits assistant (Track B)

ClaimCheck answers benefit questions for members of a fictional Indian insurer, **Asteria Health**, with a cited
plan document for every number. It estimates what a member pays on a hospital bill, checks waiting periods, and
drafts claim appeals that a claims reviewer must confirm. All amounts are in Indian rupees (₹).

It uses only a hosted ≤8B chat model and an embeddings endpoint; nothing is trained. The 600 documents,
15 members, 8 claims and 98 evaluation questions are generated by seeded code, so every correct answer is known.

Built from the PolicyPilot starter (same structure, new domain). Specification: `docs/SPEC.md`.

## Quick start (laptop)
```bash
pip install -r requirements-dev.txt
python scripts/build_data.py          # 600 documents, 15 members, 98 eval items
python -m pytest tests -q             # 57 tests, no model or secrets needed
cp .env.example .env                  # then fill in the endpoint details
python scripts/smoke_test.py          # checks the chat and embeddings endpoints
python scripts/ask.py "What is the ICU cap per day on the Gold plan in zone C?"
python scripts/ask.py "I have a ₹1,20,000 hospital bill with 3 days in a ₹9,000 per day room. How much will I pay?" --user M003
streamlit run app/streamlit_app.py
```
On Google Colab, use `notebooks/ClaimCheck_Colab.ipynb` (secrets go in the Colab Secrets panel).

## How a question is answered
1. **Guard** (`guard.py`, plain code): refuses medical, diagnosis, outcome-promise, other-member, legal, fraud and
   injection requests, and asks back when the plan tier and zone are missing. No model call.
2. **Planner** (model, JSON): picks one tool per step, at most 10 steps.
3. **Executor** runs the tool:
   `search_plan_docs`, `get_member_profile`, `cost_share_calculator`, `waiting_period_checker`, `create_appeal_draft`.
4. **Writer** (model, JSON): answers from the evidence only, with citations.
5. **Critic** (code + one model check): rejects invented citations, superseded 2024 documents, the wrong tier or
   zone, numbers not in the evidence, cost answers without the calculator, and promises of approval.

## Settings (`.env` or Colab Secrets)
`LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`, `EMBED_MODEL` (required); `LANGFUSE_PUBLIC_KEY`, `LANGFUSE_SECRET_KEY`
(optional tracing); `EMBED_BASE_URL`, `EMBED_API_KEY` (only if embeddings are served elsewhere); `EMBED_PROVIDER` (`endpoint`, or `local` to run the embedding model on this machine: a fallback that needs mentor approval and `requirements-rerank.txt`); `CC_DATA_DIR`, `CHUNKING`, `MAX_STEPS` (10), `TOKEN_BUDGET` (12000), `RATE_LIMIT_PER_MIN` (10),
`USE_CACHE` (set 0 for official runs), `PRICE_PER_1M_TOKENS` (an assumption: state yours in the report).

## Demo users
Members M001–M015 cover every tier and zone. M003 (Silver, zone B) has a declared pre-existing condition and a
rejected claim C0031 to appeal. Sign in as **Claims reviewer** to confirm or reject draft appeals.

## ClaimDesk: multi-agent claims adjudication (in progress)

ClaimDesk decides a submitted claim (approve, part-pay, reject or pend, in ₹) with a team of agents, and a
claims reviewer confirms every draft. It reuses ClaimCheck's corpus, calculator, guard, LLM client and tracing.
Specification: [ClaimDesk spec](https://claude.ai/artifact/NWvSYPJBZAhQ3ANFM2TVq8). Design notes: `docs/CLAIMDESK.md`.

```
python scripts/build_claims.py                         # members, hospitals, codes, 800 past claims, test + dev claims
python scripts/decide_claim.py CL2001                  # one claim, with every agent's tool calls
python scripts/run_claimdesk_eval.py --system full     # 33 dev claims (tune prompts here, never on test)
python scripts/make_claim_pdfs.py --free-layout       # claim PDFs to upload -> data/claims/pdf/dev/
python -m streamlit run app/claimdesk_app.py           # reviewer app: upload a claim PDF, or pick a dev claim
```

| Code | What it does |
| --- | --- |
| `src/claimdesk/gen.py` | Seeded claims: 150 test (frozen for official runs) + 33 dev, gold labels from the rules |
| `src/claimdesk/tools.py` | 9 tools, each limited to the one claim being decided |
| `src/claimdesk/agents.py` | Intake, Policy, Coding, Fraud, Adjudicator, Letter writer: prompts, loops, budgets |
| `src/claimdesk/rules.py` | Hard decision rules in code; the gold labels use the same rules |
| `src/claimdesk/orchestrator.py` | Intake, then 3 specialists in parallel, rules, Adjudicator, letter, draft store |
| `src/claimdesk/baselines.py` | System A (one prompt) and B (one agent, all tools) |
| `src/claimdesk/pdf_claims.py` | Claim PDFs: write packets, read an upload (form rules, else the model), check every value |
| `src/claimdesk/evaluate.py` | Scoring, ablation systems A-D, failure taxonomy |
