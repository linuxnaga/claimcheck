# Model card / system card: ClaimCheck v1.0.0
Filled from the official runs of 2026-10-30 (eval-v1, 3 runs each, cache off).

- **Intended use:** answering benefit questions for the fictional insurer Asteria Health. Advisory only;
  cost figures are estimates, not claim decisions.
- **Not for:** medical or legal advice, real claims, real member data.
- **Model:** `Qwen/Qwen2.5-7B-Instruct-AWQ` used through an API; no weights changed. Embeddings: `BAAI/bge-small-en-v1.5` run locally (the endpoint has no embeddings route; mentor-approved).
- **Data provenance:** 600 documents generated by `src/claimcheck/corpus_gen.py` (seed 42, reproducible);
  15 members and 8 claims are fictional. No real personal data. Amounts in Indian rupees.
- **Evaluation:** 98 items (`data/eval/eval_set.jsonl`), 3 runs, cache off. Accuracy 99.0% ± 0.0,
  citation accuracy 98.7%, completion 98.0%, average tokens 3,163, average latency 10.6 s, p95 44.2 s.
  Single-prompt ablation 65.3%.
- **Known failure modes:** (1) the model support check can reject a correct answer (1 of 98, fact-002, escalated to the helpdesk);
  (2) the planner sometimes repeats a tool call (caught by the loop guard, 1 of 98, answer still correct);
  (3) p95 latency 44 s from endpoint rate limiting.
- **Refusal behaviour:** rules in `guard.py` (medical, diagnosis, outcome promise, other members, legal,
  fraud, injection). Measured refusal accuracy 100% (10 of 10), injection 100% (11 of 11). Off-topic requests rely on the writer.
- **Safety measures:** document sanitiser, tool allow-list, access control on member data, PII masking
  (names, emails, phones) in logs, draft-only appeals confirmed by a claims reviewer, step/loop/token caps,
  critic that checks citations, versions, tier, zone and every number.
- **Limitations:** fictional template data; the small model can pick the distracting number in Conditions;
  rule-based guard can miss new phrasings; cost estimates ignore real-world sub-limits.
